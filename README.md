# StarBase

[linux.sb 社区](https://linux.sb) 的第三方 Android 客户端。Jetpack Compose 单 Activity，
界面按 Liquid Glass 一套玻璃语言重构，玻璃面板是真实背景采样而不是半透明色块。

站点是服务端渲染的，所以 App 没有自己的后端：OkHttp 取 HTML，Jsoup 解析成模型。登录也走同一个
客户端——登录表单和站点当前要求的验证码、工作量证明由 App 自己提交，密码只在提交那一刻过一遍内存，不写盘。
站点使用 CAP 人机验证时，点击登录或注册会弹出官方验证组件，完成后继续提交。
组件的脚本、WASM 和验证请求接入 App 的 DoH、TLS 分片及 QUIC 回退；关闭弹窗可保留已填内容。

## 站点的内容全部实时，本机只存 App 自己的东西

站点页面实时读取，不保存帖子或列表副本，也不启用 HTTP 磁盘缓存。草稿和偏好属于本机数据；
用户主动保存或分享的图片会写入所选位置或短期分享目录。截图求助生成的编辑副本存入应用私有的
`files/vision_drafts/`，随所属草稿保留；移除附件、删除草稿或确认上传后清理对应文件。

判断一样东西该不该存在本机，看它有没有服务端：

**收藏有**，所以它是站点的收藏，不是本机清单。帖子页上的按钮读页面上的真表单（POST
`/topic_favorite`）再提交，按钮上的字用站点自己的字；「我的收藏」就是
`/user/{uid}?tab=favorites`。手机上收藏完，网页上那一页里就有——两边是同一份数据，不是两份。
所以网页上取消的，App 里刷一下也就没了。

「成没成」这件事是**比出来的**而不是猜的：提交前后各读一次那个按钮，`Parse.favoriteChange`
比较两者。原因是我们手上没有「已收藏」状态的抓取（那次抓取的账号没收藏过那个帖子），不知道站点给
这个状态用的是哪个 class；而「按钮跟刚才不一样了」这个判断不需要知道。站点把按钮换了词但两次都被
读成同一个状态时，按「它确实变了」处理并翻转，不是报一句错的「已取消收藏」；两次完全一样时，
App 直接说「站点没有确认这次操作，去网页看一下收藏列表」——不假装成功，这是 v1.0.1 那个回帖 bug
教的。

**浏览历史没有**——站点根本不记你看过什么。所以它反过来，是 App 自己的功能，本机是它唯一能待的
地方：按自然日分组、同一个帖子记「看过 N 次」而不是列很多遍、能按标题 / 板块 / 帖子号搜、单条能删、
整份能清、也能直接关掉不记。存的是**你做过什么**（id、当时的标题、板块、时间、次数），不是帖子的
副本——点开任何一条都是去取最新那一页，标题改过就显示新的。上限 300 条。入口在「应用设置」里，
不在「我的内容」那个矩阵里，因为那八格是 linux.sb 的内容。

1.0.3 及更早版本里，这两样都是存在本机的清单，收藏那一份跟网站毫无关系；1.0.4 分开了，升级上来会
在第一次启动时把旧的几个键抹掉。

### 站点没有服务端的那几样，才落在本机

1.1 之后（1.1.1、1.1.2）又加进来的那几个功能都过同一道关：站点有没有这件事的服务端。都没有，所以它们是 App 自己的
功能；而存下来的一律是**你做过什么**，不是站点内容的副本。

- **读到哪儿了 / 追帖。** 每个帖子存一个位置：看到第几楼、当时它一共有多少楼、时间，还有当时的
  标题。重开一个看过的帖子，顶上那条「上次读到 12 楼」就是这么来的（它**不会一直挂在那儿**：
  约三秒后自己收起，因为该说的一句话已经说完了，而下面是要读的帖子）。「追帖看板」把标了追的帖子
  列在一起，打开时每个帖子取一次页面，「多了 12 条」是现取那页自己报的楼数减掉存的那个数——
  是对新鲜页面做的减法，不是存了一份帖子。位置上限 300 条，追帖最多 20 个（一次并发取 4 个）。
- **常去板块 / 板块自选排序。** 「常去」是每次画的时候从浏览历史现算的，一条都没有存；存的只有你
  钉的板块和你选的排序模式（站点顺序 / 常去优先 / 自定顺序）。所以把历史关掉，常去那一条就直接
  消失，而不是留下一份过期名单。板块卡上「120 主题」是站点给的数，「去过 5 次」是 App 自己数的，
  两个数并排显示，不合成一个。
- **抽奖开奖提醒 / 签到提醒。** 开奖时间是站点自己的字段：抽奖帖的主楼底下有一张抽奖卡，上面印着
  「到 2026-09-04 09:12自动开奖」，App 现在照它的位置把这张卡画出来，「开奖提醒」就在这一行的旁边。
  写着「满 500 人自动开奖」的那种只有这句话、没有按钮——没有人知道第 500 条回复什么时候来。
  存的是提醒本身：时间、标签、对应的帖子号。设好之后交给系统的
  `AlarmManager`——**不联网、不轮询、也不是推送**，就是本机一个闹钟，响的时候也不发请求。闹钟活
  不过重启和升级，所以每个进程起来时把还没到点的重新挂一遍。上限 40 条，签到固定一条（默认
  早上 9:30），重设是替换而不是叠加。
- **本地屏蔽 / 折叠。** 关键词和用户两种规则：命中的主题在首页 / 板块 / 搜索 / 用户主页里收起来，
  命中的回帖在帖子里折叠。上限 60 条。**站点自己也有关键词屏蔽**
  （`/home_keyword_filter_settings`，首页上那个「屏蔽设置」），本机这份不替它、也不碰它——站点
  那份只管首页、只认关键词，这份还管板块页、搜索结果和用户主页，也能按人折叠一个帖子里的回帖，
  那是站点完全没有的概念。屏蔽规则页上有一个入口直接打开站点那一页。按人的那种规则不用手打名字：
  用户主页顶栏上「屏蔽」按一下就是一条，页面本来就知道这是谁，而手打的名字是唯一可能打错的版本。
- **分享成图。** 入口在每一楼上：一楼 meta 那行最后那个「箭头出盒子」的图标（主楼的在正文下面
  那行动作的右端），点开是一张能看的预览再决定发不发。这一样什么都不存：把那张卡（板块、楼层、
  标题、正文摘要、作者和时间、星标 + linux.sb）当成一个真的 composable 画进离屏图层再读成位图，
  所以**预览就是导出的图**，没有第二条绘制路径、也不是截屏。PNG 落在 App 自己 cache 的 `share/`
  里交给系统分享面板，出新的时候把一小时前的清掉。卡上不带分享者是谁。

被藏起来的东西**永远会报数**。每个过滤过的列表末尾都有一行「N 条被本地规则藏起来了」，点「看看」
把它们连着「是哪条规则藏的」一起展开。这不是装饰：一个默默少了三条的列表，和站点上那一页内容
本来就少，在屏幕上长得一模一样；而一条写得太宽的规则也只有这样才找得出来。搜索结果那一行是无条件
显示的——搜一个被屏蔽的词却把命中的帖子藏掉，那没道理。

### 域名解析 (DoH)

站点打不开、或者打开的不是站点，很多时候是这台设备拿到的 DNS 答案不对。所以域名解析**默认就是开着
的**：域名交给你选的 DoH 服务器解析（RFC 8484 wireformat，`net/Doh.kt` 自己编解码），答案裹在 TLS
里，路上改不了。开关和服务器都在 `应用设置 → 域名解析 (DoH)` 里，随时能关回系统 DNS。

默认开着是有代价的，就写在这儿：每解析一个域名要多问一次第三方，那台服务器也就知道了你在解析哪些
域名（**只是域名**，看不到你在站点上做什么）。默认之所以是开，是因为答案错的时候，App 就打不开——
而打不开的人是读不到这一页的。出厂默认那台是 `dns.telekom.de`（德国电信自营的解析器），卡上七个
预置随便换。

- 七个预置服务器**按可达性排过序**：打包前直连实测（2026-09-02，不走代理）只有前三台答得上来，
  后四台的 TLS ClientHello 一带上自己的域名就被 RST——跟站点被掐的是同一种拦截，不是它们坏了，
  换个网络照样能用，所以留在单子上。也能自己填一个 `https://…/dns-query`；卡上的「测试」就地问
  一次 `linux.sb` 的 A 记录，把耗时和拿到的地址印出来，好过让人猜「这台能不能用」。
- 解析结果按记录自己的 TTL 缓存（夹在 30–600 秒之间），换服务器就清空。TTL 到点之后那条答案不马上
  扔，再留 30 分钟当**过期备用**：重问不成的时候先用它顶着。一个上一次还对的地址，比一个被污染的新
  答案有用得多。
- **DoH 失败会尝试备用解析**：任何一步不成（连不上、答案是空的、返回的不是 DNS 消息）都先用上面
  那条过期答案顶着，没有才退回系统 DNS，卡上会写出上一次失败的原因。两边都不成才向调用方抛
  `UnknownHostException`。
- 失败一次就**把 DoH 搁一分钟**。默认开着的东西必须有这一条：一台连不上的服务器否则会让每个域名都
  先等满超时（4 秒连、6 秒封顶），而失败不像答案那样会被缓存，于是每个新域名都要再等一遍。但搁着**只
  是这一分钟里不再去问那台服务器**：问过的域名照旧用过期答案回答，只有连过期答案都没有的名字才落到
  系统 DNS。一分钟后它自己回来，不用你去按什么。
- **没自己选过服务器的话，答不上来就自己换一台。** 出厂那台在某些网络上就是不通（见上面那条实测：
  七个预置只有前三台答得上来），而一个默认开着的功能不该把人留在一条死路上：解析失败的时候，App 在
  后台并发问剩下六台预置同一个 `linux.sb` 的 A 记录，答得上来的里面取最快的那台换过去，8 秒没人答
  就这次算了。换出来的那台单独记着（`doh_server_auto`，跟你自己选的那一栏分开存），下次启动直接用。
  两条硬规矩：**自己在卡上选过一台，就永远按你选的来**，App 不会替你改；换服务器这件事最多十分钟
  一次，免得一个没网的地方把它变成后台一直在测速。
- 站点请求和图片请求走同一个客户端，所以头像和帖子里的图跟页面一样按这条路解析；查新版本的
  `api.github.com` 也用同一个解析器——网络在名字上说谎的时候，它对 github.com 一样说谎。
- **它只治解析这一段。** 地址本来就是对的、连上去之后才被掐断（按 TLS `server_name` 打的那种），
  换谁解析都一样。写这一版的时候，linux.sb 在打包这台机器上**恰好就是后面这一种**：DoH 给回来的
  地址没错，但 TLS 一带上 `server_name=linux.sb` 就立刻收到 RST；同一个 IP 换个别的域名握手就
  成功。那一半是下面两张卡（**分片 (TLS)** 和 **QUIC 回退**）在管的，三节要连着读。
- **登录那一页现在也走这里。** 它以前跑在系统 WebView 里，自己解析、自己建连，所以这上面的功夫
  一处都到不了它。现在登录、注册由 App 自己用 OkHttp 走完（`Api.loginForm` / `Api.login`），
  验证码和工作量证明按站点当前表单决定是否启用，与其他页面共用客户端、解析器和回退策略。
  CAP 弹窗通过资源拦截和官方 `CAP_CUSTOM_FETCH` 接入同一网络配置，直连验证服务；不使用系统 HTTP 代理，
  不向验证服务附带账号 Cookie。它只允许当前表单指定的验证资源和接口。
  跟着一起没了的是本机那个回环转发口：它当初只为了把 DoH
  和分片送进 WebView 而存在，而它没有口令、Android 上的回环也不是私有的，所以能删掉是净收益。
- 还有一处绕不开的先后顺序：DoH 服务器**自己的**域名只能由系统来解析（它不能自己解析自己）。这一步
  给了 1.2 秒上限，因为 Android 上的 `getaddrinfo` 打断不了：老实等下去的话，光是服务器的名字解析卡
  住，就能在发出第一个 DoH 字节之前把每个域名的 6 秒预算花光。所以它跑在用完就扔的后台线程上，到点
  就按失败处理，迟到的答案照样收进缓存（10 分钟内直接用，之后再留 50 分钟当过期备用；解析不出来的时
  候，旧答案也好过没有）。碰上「连服务器的名字都答错」的网络，就在自定义那一栏直接填一个按 IP 的地址
  （例如 `https://1.1.1.1/dns-query`）——证书对 IP 也是验的，跳过解析这一步。

### 分片 (TLS)

DoH 治不了的那一半在这儿：地址是对的，TCP 也连上了，TLS 握手一带上 `server_name=linux.sb`
就立刻收到 RST——同一个 IP 换个别的域名握手就成功，所以拦的是**名字**，不是地址。

把带名字的那一段**切在域名中间**，两截各拿到半个名字，中间设备就拼不出 `linux.sb`
（`net/Frag.kt`：认出 ClientHello、找到 `server_name`、在名字中间切一刀，两次 `write`
中间隔 20 毫秒，`TCP_NODELAY` 保证它们不会被 Nagle 合回一个包）。切在更前面没用——整个名字会完整地
待在第二截里，所以要点不是「切开握手」，是「切开名字」。

**切法有两种，赢的是不同的设备：**

| 切法 | 线路上看到的 | 赢得了 | 输给 |
| --- | --- | --- | --- |
| `Style.SEGMENT` | 一条 TLS 记录，两个 TCP 包 | 逐包看的设备 | 会把 TCP 流重组起来的 |
| `Style.RECORD` | 两条 TLS 记录，各一个包 | 上面那种，**加上**会重组 TCP、但假定一条记录里装着一整个握手消息的 | 两样都重组的 |

`RECORD` 是合法 TLS——RFC 8446 §5.1 明说一个握手消息可以跨记录，只有记录头变了，握手字节和顺序
都没动，两个长度加起来还是原来那一条的长度，所以服务端看两种切法一模一样（Cloudflare 收下并完成了
1.3 握手，本地验过）。「一条记录装一整个消息」是很常见的偷懒，因为做对就得缓存，所以多这一种切法
是白捡的。**开关打开的是 `RECORD`**，`SEGMENT` 留给「测试」当对照。

两样都重组的设备这一刀就不够了——所以它是**默认关着**的一个开关，旁边配一颗「测试」，而不是一句承诺。

开关在 `应用设置 → 分片 (TLS)`。**默认关着**，跟默认开着的 DoH 不一样，这两个看着像同一类开关
其实不是：DNS 答案错是常见事，而 DoH 的答案要么对、要么退回系统，开着在哪个网络上都不亏；这一个
是在赌某个中间设备拿一个被拆开的记录会怎么办——没人掐你的线路上它一文不值，不按「测试」也没法知道
到底有没有用。这不该塞给一个没提过这要求的人。

- 「测试」**先问 DNS 和 ECH 公钥，再连最多四次**。第一行是**它到底连到哪个地址**：DoH 说的、系统 DNS
  说的、两边有没有对上（Cloudflare 会按解析方给不同的 anycast 地址，所以「不完全一样」不算被改，
  「一个都不重叠」才算）。这一行最要紧：「地址被改了」和「名字被掐了」在屏幕上长得一模一样，没有它就
  分不开。第二行是 **ECH**：这个站的 `ech=` 公钥取到了没有、里面登着的公开名字是什么、这台设备有没有
  那个接口——两样都齐了，下面才多一次「名字加密发出去」的连接。往下是真连接——名字加密、两条记录、
  两个 TCP 包、完全不拆——各印耗时、连的哪个地址、TLS 版本和拿回来的状态行，或者失败原因
  （`Connection reset` 会写成「连接被重置（RST）」，因为「被 RST」和「超时」说的是两件事）。
  这个顺序是排过的：ECH 那次在最前，它是唯一一次线路上根本没有名字的连接，最值得先问，也最不会把
  这个地址撞得关一会儿；不分片那一次在最后，它是**故意**去撞拦截的对照，有些设备撞完会把这个地址
  关一会儿。取不到公钥、或者这台设备没那个接口，ECH 那一行就只报事实、不多连一次——没装上配置的 ECH
  就是那个对照，而把对照排在最前正是这套顺序要避开的事。
- **每行末尾还印分片有没有真的发出去**（`FragSocket.wrote` / `.split`）。分片唯一可能悄悄失效的
  地方是 TLS 库压根没走这条流：Conscrypt 有两种 socket 实现，只有叠在别的 socket 上那种会把记录写进
  底下那个 `OutputStream`，`Frag` 的 `init` 会去要那一种（`org.conscrypt.useEngineSocket`），
  但要不到也是可能的。那种失效在屏幕上跟「分片没用」一模一样，所以这里报事实，不报推测。
- 探测不止握手，还要真发一个 GET 读回状态行。晚一拍才到的 RST（握手过了，第一个应用数据包才被断）
  在只看 `startHandshake()` 的眼里跟成功一模一样。
- 几行印完给一句结论，而且**认得三个陷阱**：分片没真的发出去，就说「这几次其实是同一种连接，还不能
  说明分片没用」；DoH 和系统 DNS 的地址不重叠，就说「先治解析，再回来试分片」；连 ECH 那一次都不通，
  就说线路上根本没有 `linux.sb` 可看却还是被掐，那就不是按名字拦的，别再往分片上使劲。
- 它同时也管 `Doh` 自己的请求：七个预置里有四台就是因为**它们自己的** `server_name` 被 RST 才不
  可达的，分片正好是唯一能对这件事做点什么的东西。
- **登录那一页也一起吃到了**，而且不再需要为它开任何东西。登录以前跑在真 WebView 里，WebView 有
  自己的网络栈，OkHttp 的 `Dns` 和 socket 工厂都到不了它，所以那时候要在本机回环上起一个只转发
  `CONNECT` 的口把它牵过来。现在登录是 App 自己用 OkHttp 发的表单（见上面「域名解析」那一节），
  分片、DoH、QUIC 回退它一样不落，那个没有口令的回环口也就一起删掉了。
- **它不是代理，也就治不了别的。** 包还是发到站点自己的地址：按地址封的、或者会重组 TCP 流再看的，
  它都治不了。真能对付重组型设备的手段（低 TTL 的假 ClientHello、故意乱序的分段）要发原始包，
  那要 VPN 权限，这个 App 不申请。剩下的就是这一刀，值得试，因为它每条新连接只多花一次 `write`。
  重组型设备真正的答案在下一节：换掉 TCP。
- **它不是 ECH——不过 ECH 这个 App 现在自己有了。** 先把「浏览器开了 DoH 就能打开、这个 App 不行」
  说清楚：那不是 DoH 的功劳。浏览器打开安全 DNS 之后会顺手取站点的 `HTTPS`/SVCB 记录，`linux.sb`
  的那条记录里登着一个 `ech=` 公钥（Cloudflare 的，`public_name=cloudflare-ech.com`，`alpn=h3,h2`），
  于是浏览器把**真名字加密在握手内部**发出去，线路上根本没有名字可看，也就没什么可掐——Chrome 和
  Firefox 都把 ECH 绑在安全 DNS 上，关了安全 DNS 就没有 ECH，所以那看着像 DoH 的功劳。
- **同一条路现在这个 App 也走**（`net/Ech.kt`）：`Doh` 取那条 `HTTPS` 记录里的 SvcParam 5，交给系统
  TLS 去封。要三样东西同时到位，其中只有一样是我们的：
  - **公钥**是站点的 CDN 已经在登的，不需要站点配合——这一点对第三方客户端是关键，`linux.sb` 不是
    我的站，我改不了它的 DNS，而这件事根本不用改。它是**走 DoH 取的**，不走系统解析：一把在明文
    DNS 里取来的公钥可以被同一个中间设备换掉，拿它加密就只是演戏。
  - **接口**是 **Android 17（API 37）** 才有的 `android.net.ssl.EchConfigList` 和
    `SSLSockets.setEchConfigList`——正好是这里要的形状：配置由 App 给，所以它既不等 OkHttp 支持 ECH，
    也不要求你打开系统的私人 DNS。`compileSdk` 是 36，所以按反射取，而且是**按形状找**而不是按签名
    找：签名对不上就当这台设备没有，不在谁的手机上崩。
  - **开关**是 `res/xml-v37/network_security_config.xml` 里的 `<domainEncryption mode="enabled"/>`，
    targetSdk 低于 37 时它默认关着，所以要显式写出来。
- **它跟分片是两件不同性质的事。** 分片是在赌某个中间设备拿一个被拆开的记录会怎么办；ECH 不赌——
  线路上的名字就是 CDN 那个公开名字，真名字封在里面，没有东西可认。所以 ECH **没有开关，也不需要你
  开**：设备有这个接口就自动用上（`Net.client` 只在 `Ech.available` 时才换 socket 工厂，低版本上那条
  客户端一行都不变），用不上的设备剩下的才是分片。「测试」里 ECH 那一行写的就是这台设备到底用上了没有。
  代价只一样，也写在这儿：取公钥要一次 DoH 往返，压在**建 socket 的时候**——每个域名每半小时最多一次，取不到也
  记着，所以没有 `HTTPS` 记录的域名不会每条连接都再问一遍。
- **登录那一页现在也在 ECH 的范围里。** 那一段握手以前是 WebView 自己发的，`Net.client` 的 socket
  工厂管不到；现在登录就是这个客户端发的一个表单 POST，所以 ECH、分片、QUIC 回退对它一视同仁。
- 开关是在**建 socket 的时候**读的，不是写的时候。这样 OkHttp 连接池里已经在用的连接会保持它
  被建立时的行为——否则中途翻开关会把一条活着的 TLS 流切在半路，那不是藏名字，是弄坏它。
- 哪一段字节落在哪个包里就是这个功能的全部，所以 `Frag.write` 收的是一个 `OutputStream`
  而不是 socket：`FragTest` 递给它一个记下每次 `write` 边界的流，20 个用例全在 JVM 上跑，不联网。
  ECH 那半边同理，只测能测的：平台那一个调用在 JVM 上根本不存在，所以 `EchTest` 的 11 个用例打在两个
  解析器上——从一条 DNS 应答里挑出 `ech=`（连同「记录里没这一项」、「AliasMode 不带参数」、「乱码
  不许抛」），和从一个 ECHConfigList 里读回公开名字（连同不认识的版本要跳过、长度不够的要丢掉而不是
  猜）。里面那些线路上的数字（版本号、参数键号）是照 RFC 手写的字面量，不从 `Ech` / `Doh` 里取：跟着代码写同一个常数的测试，
  只会在两边一起错的时候一起点头。

### QUIC 回退（HTTP/3）

分片赌的是中间设备拿一个被拆开的 TLS 记录会怎么办。会重组的设备赢了那一注，而对它们真正的答案不是
切得更碎，是**换掉 TCP**：QUIC 跑在 UDP/443 上，它的 ClientHello 装在一个加密的 Initial 包里。

`net/CronetFallback.kt` 是一个 OkHttp 拦截器，首次在 TCP/TLS 失败后，把同一个请求交给
Cronet（Chromium 的网络栈，`cronet-embedded`，自带 native 库，不依赖 Google Play 服务）重发一次。
回退成功后，同一网络、域名和端口的 GET/HEAD 请求在五分钟内优先复用该通道；通道失败、网络或解析配置改变、
记录到期后重新选择。TCP 建连和 TLS 握手的单次等待上限为四秒，连接建立后恢复原有读取超时。
三行配置是关键：`enableQuic(true)`；`addQuicHint(host, port, port)`，因为 QUIC 通常要先经 TCP 上的
`Alt-Svc` 学一次，而 TCP 正是断掉的那一段；以及 `HostResolverRules` 的 `MAP host ip`，把地址钉成
App 用 DoH 解出来的那一个——Chromium 自带的解析器走系统 DNS，一个被投毒的答案会让 QUIC 的证书校验
直接失败。引擎按「策略 + 域名 + 端口 + IP」分开缓存，最多六个，DoH 设置一变就整池作废。

打这一版的机器上量到的（物理网卡，绕开本机的 TUN）：

| 发法 | 结果 |
| --- | --- |
| TCP，`server_name=linux.sb` | 27 毫秒收到 RST |
| TCP，不带名字 / 换个名字 | TLS 1.3 握手完成 |
| QUIC Initial，SNI=`linux.sb`，两个地址各四次 | **八次全部有回应**，220–455 毫秒 |

那个 RST 比一条 200 毫秒 RTT 的连接的一个来回快得多，所以它是本机附近的盒子注入的；而同一个名字
装在 QUIC Initial 里就没人管。Initial 只用从连接 ID 推导出来的公开密钥保护，任何中间设备都能解开
看——这条线路上的那个只是没做。

**所以它是一注赌，不是定理**，写在「已知限制」里：有能力解 QUIC Initial 的设备存在，很多网络还直接
封 UDP/443。它只重试能安全重放的请求（`https`、非一次性请求体、证书错误不重试、已经发出去的写操作
只有 `GET`/`HEAD` 才重发），失败时抛回**原来那个** TCP 错误，界面上的说法不变。

代价是体积：Cronet 每个 ABI 一个 3.5–5 MB 的 `.so`，安装包从 2.3 MB 涨到 arm64 的 7.2 MB。所以
release 按 ABI 分包（`armeabi-v7a` / `arm64-v8a` / `x86_64` 各一个，外加一个 21 MB 的 universal），
更新检查按 `Build.SUPPORTED_ABIS` 挑对应那个，universal 只作兜底。

### 这几样的入口在哪儿

本机功能最容易出的问题不是不好用，是找不到。所以它们的入口一律放在**用得到它的那个页面上**，
「我的 → 本机」和「应用设置」只是清单和开关：

| 功能 | 入口 |
| --- | --- |
| 读到哪儿了 | 打开一个看过的帖子，标题上方自动出现「上次读到 12 楼」，约三秒后自己收起；「回到那里」跳回那一楼，「不用」立刻收起 |
| 追帖 | 帖子页**顶栏**上「追帖」，就在「收藏」左边；开着的时候那颗药丸会亮，字变成「已追」 |
| 追帖看板 | 我的 → 本机 → **追帖**（应用设置 →「读到哪儿了」那张卡里也有一个入口） |
| 签到提醒 | 我的 → 本机 → **提醒** → 「签到提醒」那张卡按「打开」；时间默认早上 9:30，卡上能改成 8 / 9 / 12 / 20 / 22 点 |
| 开奖提醒 | 抽奖帖里，主楼正文下面那张**抽奖卡**上，「开奖时间」那一行右边——按定时开奖的才有，按人数开奖的只印条件不给按钮；再按一下取消，设过的也能在 我的 → 本机 → 提醒 里看和取消 |
| 本地屏蔽 / 折叠 | 我的 → 本机 → **屏蔽**（自己写关键词或用户规则）；另外在**用户主页顶栏**上按一下「屏蔽」，就是一条按这个人的规则，不用手打名字 |
| 分享成图 | 帖子里每一楼 meta 行末尾那个「箭头出盒子」的图标；主楼的那个在正文下面那行动作的右端 |
| 常去板块 / 排序 | 板块页顶上「常去」那一条，和它下面的三档排序（站点顺序 / 常去优先 / 自定顺序） |
| 浏览历史 | 应用设置 → 浏览历史 |
| 域名解析 (DoH) | 应用设置 → **域名解析 (DoH)**（默认开着；网络错误那一页也会指过来——DoH 关着说「试试打开」，开着而分片没开说「去按分片那颗测试」，两个都开着才说「换一台服务器」） |
| 分片 (TLS) | 应用设置 → **分片 (TLS)**，就在域名解析下面（默认关着；「DoH 开了还是打不开」就按那颗「测试」——网络错误那一页在这种情况下也直接指过来） |

本机 SharedPreferences 一共就这些：外观、检查更新的时机、上次查到的 release tag（用来在「我的」上
挂那个「新版本」标）、浏览历史和它的开关、每个帖子读到哪儿了和它的开关、追帖标记、钉住的板块和
排序模式、提醒清单、屏蔽规则、域名解析的开关和你选的那台 DoH 服务器（外加它自己换过去的那台，跟你
选的那一栏分开存，这样它换来换去也盖不掉你的选择）、分片的开关。每一样都是
「你做过什么」的记录；里面出现的标题是「你打开它时它叫什么」，取回新的一页之后跟着更新，不是留着给
你看的副本。

三处不是缓存但值得说清：

- 同一个屏幕在 90 秒内来回切不会重复请求（帖子页 45 秒）。这是同一次使用里的去重，不是存下来的
  副本——`ui/Freshness.kt` 只记一个时间戳，过期就重新取，进程结束即失效。图片同理：内存缓存开着
  （不然每次滚动都要重下头像），磁盘缓存关着。
- 浏览历史里存着标题，但那是「你打开它时它叫什么」的记录，不是留着给你看的副本：那一页永远是
  现取的，取回来之后记录里的标题也跟着更新。
- 登录不缓存任何东西，因为它没有什么可缓存的：`_csrf`、验证码 token、工作量证明前缀都是一次性的，
  每次打开登录页都重新取一份。密码只在你按下「登录」的那一刻存在于内存里，随表单一起发出去就没了
  ——App 不写、不存、也没有「记住密码」这一项。留下来的只有 cookie，在系统的 `CookieManager` 里，
  跟别的页面共用同一份会话。

## 写操作

回帖（可引用楼层）、发新帖、点赞 / 投币、收藏、发私信。都是原生请求，不套 WebView。

站点没有 JSON API，这些表单只在登录态页面里才有。**字段名一律从页面上的真实表单读，不写死**
——`Parse.formOf` 读出 action、method、enctype 和每一个可提交字段，调用方只覆盖用户填的那一两
项，其余原样回发。这不是洁癖：站点自己的命名就不统一（回帖正文叫 `body`，私信正文叫
`content`），而且 `topic_special_type` 这类字段猜错会把普通帖发成抽奖帖。

| 操作 | action | 正文字段 |
| --- | --- | --- |
| 回帖 | `/reply_edit` | `body` |
| 发帖 | `/topic_edit`（表单无 action，发回自己） | `body` |
| 评论点赞 | `/donate_reply_reaction` | 无，用 `donate_reaction_points` |
| 主楼打赏 | `/donate`，要先 XHR 取 `/donate?topic_id=` 拿一次性 `request_key` | 无，用 `amount` |
| 收藏 | `/topic_favorite`（表单带 `data-no-ajax`，回的是页面不是 JSON） | 无，用 `topic_id` |
| 私信 | `/direct_messages/{对方uid}` | `content` |
| 附件 | `/attachment_upload`，独立端点 | 无，`attachment` 是文件部分 |
| 改资料 / 简介 / 密码 / dicebear 头像 | `/profile`（表单无 action，发回自己） | `bio` |
| 改用户名 | `/username_change` | 无，用 `new_username` + `current_password` |
| 改邮箱 | `/user_review_email_change`，先 XHR 取 `/user_review_email_code` 发码 | 无，用 `email` + `email_code` |
| 头像上传 / 选预设 | `/avatar_upload`，独立端点 | 无，判别字段 `avatar_upload_action` |

主楼和评论的点赞是**两套无关的机制**：评论的表单就在页面上，主楼页面上只有一个链接，真表单在
`/donate?topic_id=` 的 JSON 里，且 `request_key` 一次性，不能缓存。

附件也不是表单字段：POST 文件到 `/attachment_upload`，响应里的 `markdown` 才是要插进正文的东西。

开新会话不需要额外接口——用户搜索的每条结果都直接指向 `/direct_messages/{uid}`，那个页面对从没
聊过的人一样渲染发送框，空会话就是新会话。

`/profile` 那一张表单同时管着头像风格、简介和密码三件事，所以改任何一项都是整份读回、只覆盖
那一项再提交。改用户名的两个输入框用 HTML5 的 `form=` 属性从表单**外面**关联进去，同时又正好
坐在 `/profile` 表单里——两个方向都要算，否则改名提交出去只有一个 token，或者保存资料时顺手
提交一次改名。

引用楼层不是表单字段：站点的回帖处理器从正文文本里认 `@某人 #12`，所以 `Parse.quotePrefix`
负责写、解析层负责读，两个方向有往返测试互锁。

表单如果带 Cloudflare Turnstile（目前没有），原生请求做不出那个 token——那时候只能把这一页交给
浏览器处理。CAP 验证由 App 内的官方组件完成，结果随原生表单提交；算术验证码和 SHA-256 工作量证明
启用时仍按原流程处理。CAP 缺少配置时会报加载错误，避免漏带验证结果直接提交。

### 抓登录态页面

写操作的表单、点赞按钮的积分档位、私信会话的结构，游客都看不到。要改这部分先抓一份：

```powershell
# 浏览器 F12 → Network → 刷新 → 第一个请求 → Request Headers → 复制 Cookie: 后面整串
# 存进 _grab-cookie.txt（在 .gitignore 里）
powershell -ExecutionPolicy Bypass -File _grab.ps1
python _tools/mkfixtures.py        # 脱敏后写进 app/src/test/resources/
```

`_grab/` 和 `_grab-cookie.txt` 都不进仓库——原始页面带 session 和 CSRF。只有脱敏副本入库。

三个坑记在这里省得再踩：

- PowerShell 5.1 的 `Invoke-WebRequest` 会忽略手设的 `Cookie` 头（要用 `WebRequestSession` +
  `CookieContainer`），失败形态是 200 + 登录页，看着像成功。
- `$home` 是只读变量，赋值静默失败，后面所有正则会去匹配用户目录路径。
- **不要用 `Get-Content -Raw` + `Set-Content` 改带中文的文件。** PS 5.1 按 ANSI 解码再按 UTF-8
  写回，中文会双重编码成不可逆的乱码。改文本用编辑器或 Python。

## 构建

需要 JDK 17、Android SDK（platform 36 + build-tools 36.0.0）、Gradle 8.14.5。

> **仓库不含 Gradle wrapper**，请用系统装的 Gradle（版本不要低于 8.14），或自己
> `gradle wrapper --gradle-version 8.14.5` 生成一份。

先写 `local.properties` 指向你的 SDK：

```properties
sdk.dir=/path/to/Android/sdk
```

然后：

```bash
gradle :app:assembleDebug          # 调试包
gradle :app:testDebugUnitTest      # 单元测试
gradle :app:assembleRelease        # 发布包，输出 app/build/outputs/apk/release/StarBase-arm64-v8a-V1.2.0.apk 等 ABI 包
```

release 走 minify + 资源压缩。签名读仓库根目录的 `keystore.properties`：

```properties
storeFile=keystore/your-release.jks
storePassword=...
keyAlias=...
keyPassword=...
```

这个文件和 `keystore/` 都不在仓库里；缺失时 release 会自动回落到 debug key，项目仍然能编译。

### DoH 联网验收

本轮结果与未完成的设备验收见 [2026-09-06 验收记录](docs/verification-2026-09-06.md)。

普通单元测试不依赖公网。需要核对当前网络上的真实连接时，在 PowerShell 中运行：

```powershell
$env:STARBASE_LIVE_DOH='1'
gradle :app:testDebugUnitTest --tests '*DohConnectivityTest' --console=plain
Remove-Item Env:STARBASE_LIVE_DOH
```

验收使用默认 `dns.telekom.de`，禁止网站域名回退到系统 DNS，禁用 HTTP 代理，验证首页和登录页的 HTTPS
响应及原生登录表单解析。DoH 服务自身的域名仍通过有超时限制的系统解析引导。启用该开关后，Gradle 不复用
旧测试结果，避免网络状态变化时误报通过。测试不提交账号密码，也不验证 Android 上的 Cronet 原生库或界面。

应用实际运行时仍保留既有容错策略：DoH 失败先尝试可用的旧记录，没有旧记录时回退系统 DNS。
因此这项验收证明当前网络的 DoH 直连链路，不代表所有运营商网络都能连接；TLS 或 IP 封锁还需要分别排查。

完整检查命令：

```bash
gradle :app:testDebugUnitTest :app:testReleaseUnitTest :app:assembleDebug :app:assembleRelease :app:lint
```

`AuthTest.kt` 覆盖 CAP、算术及无验证码表单、匿名 Cookie 不能确认登录及注册结果核验；
`CapTransportTest.kt` 检查验证资源和 POST 请求共用指定网络客户端、请求范围、响应上限及取消。
`AuthCaptchaUiTest.kt` 检查验证弹窗、结果回传、重试和原生登录衔接，并只读检查官方组件加载。
`SessionTest.kt` 覆盖会话失效时丢弃迟到的身份和未读数响应。

写操作的用例值得单独说：它们锁的不是「解析没崩」，而是**具体字段名和 action**。回帖曾经发
`content` 到 `/topic/{id}`，站点只是把帖子页重新渲染一遍返回，于是 App 报「已提交，但未能确认
结果」——实际一条都没发出去，而当时的测试全绿。所以现在每个写操作都有一条用例直接断言它的
action 和字段集合。

25 个（`UpdateTest.kt`）打在更新检查的两个纯函数上：版本号比较和 Release JSON 解析。这两处
错了的方向都很难看——把 `1.0.10` 判成比 `1.0.9` 旧，把 `StarBaseV1.0.3` 读成版本 0，或者把附件里的
`.sha256` 当成安装包——而且都不需要网络就能测。新加的三条打在**按 ABI 挑安装包**上：一个 release
里现在有四个 `.apk`，挑错了就是让人下 21 MB 去装一个 7 MB 的东西，或者更糟，下一个跑不起来的。

17 个（`HistoryTest.kt`）打在浏览历史上。它是 App 自己的功能，没有「站点那一份」可以对照，
所以这些用例是唯一能说明它是对的的东西：置顶与计数、空标题不覆盖已有标题、上限掉最旧、按自然日
分组（含「昨天深夜」）、搜索的四种匹配、「几分钟前」在时钟被调快时的兜底，以及存取往返——特别是
标题里带引号和逗号那一条，那正是旧的分隔符拼接会坏掉的地方。`History` 的时钟是参数，所以这些
全在纯 JVM 里跑。

`DohTest.kt` 打在域名解析上：wireformat 编解码是纯函数，直接按字节断言（id 为 0、问题段、
qtype、压缩指针后面的 A / AAAA、取最小的那个 TTL）；解析器把传输层当参数收，所以测试可以塞给它一个
现成的答案或者一个失败，看它拿这个怎么办——命中缓存、TTL 到点重问、A 空了才问 AAAA、服务器坏掉先用
过期答案顶着（连过期的都没有才退回系统 DNS，并且被搁置一分钟，其间连问都不问，一分钟后自己再试）、
过期答案也过了 30 分钟才真的放手、两边都坏才抛 `UnknownHostException`。乱码那一条尤其值得有：DoH
服务器返回一页 HTML 是常事（有一台不带浏览器 UA 就回 418），解析器必须把它读成「这不是 DNS 消息」
而不是崩掉。自动换服务器和引导解析各有几条，测的都是「不该发生的事没发生」：没接线时一次探测都不发、
用户选过服务器就一台也不问、换完之后十分钟内不再换、系统解析到点放手但迟到的答案仍然被记住。这些用
例能存在，是因为时钟、线程和探测函数全是参数——它们在纯 JVM 里跑，不占秒表也不碰网络。

分片和 ECH 那两半各有一份，31 个（`FragTest.kt` 20 个、`EchTest.kt` 11 个），全在 JVM 上跑、都不
联网，理由见上面「分片 (TLS)」那一节的最后一条。

登录那一套在 `ParseTest.kt` 里另有 6 条，全部不联网。它们钉的是一次提交要带的东西：`_csrf` 的长度、
验证码题目、签名 token、工作量证明的前缀和位数（站点自己把位数掐在 2..5，所以写着 9 的页面是在要
它的默认值而不是要一台手机算到天亮）、必须空着回去的蜜罐字段，以及那张表单**到底提交哪几个字段名**
——站点改一个字段名，这里就红，而不是在手机上默默登不上。工作量证明那条不比对硬编码的 nonce，它
自己算一遍 SHA-256 验证摘要，再确认返回的是**第一个**满足条件的 nonce：站点是从 0 按十六进制往上
数的，答案又绑在签名 token 上，所以「走法一致」本身就是要求。

剩下 41 个（`LocalFeaturesTest.kt`）打在其余几个本机功能的纯函数上，理由和浏览历史一样——没有
「站点那一份」可以对照，用例是唯一能说明它们是对的的东西。挑几条说明这些用例在防什么：追帖的
「多了 N 条」在楼层数变少时不能是负数；屏蔽的用户规则比整个名字，「张三」不能连「张三丰」一起
屏蔽掉；「常去优先」里没去过的板块要保持站点原顺序，钉住的板块指向一个已经不存在的 id 时要
静静地不匹配而不是崩；开奖时间的提醒只在「还没到、又不太远」的窗口里才值得设；签到是每天一条，
重设要替换而不是叠加。开奖时间那两条测的是从正文里认日期——`2026-09-05 20:00`、`2026年9月5日
20:30`、只有日期没有时刻的 `2026/09/05` 都要认出来，而 13 月、25 点这种要返回 0
（**宁可不提醒，也不要在错的时间响**），图片里的文字更是一个字都不算。

## 隐私与网络

- 应用声明网络权限 `INTERNET`、`ACCESS_NETWORK_STATE`，更新用的 `REQUEST_INSTALL_PACKAGES`，
  提醒用的 `POST_NOTIFICATIONS`、`SCHEDULE_EXACT_ALARM`、`RECEIVE_BOOT_COMPLETED`，
  以及朗读用的 `FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_MEDIA_PLAYBACK`、`WAKE_LOCK`。
  `REQUEST_INSTALL_PACKAGES` 只让 App 有资格「请求」安装，装不装由系统自己的确认界面决定；
  Android 8+ 还要你先在系统设置里允许本应用安装未知应用，没允许时 App 直接把你送到那一页，
  而不是给一个按了没反应的按钮。
- 提醒那三个权限**不带来任何网络能力**：`POST_NOTIFICATIONS` 是往通知栏放一条，
  `SCHEDULE_EXACT_ALARM` 是让闹钟准点而不是被系统攒着一起响，`RECEIVE_BOOT_COMPLETED` 是开机后
  把闹钟重新挂上——因为闹钟活不过重启，而本机那份提醒清单是它唯一的记录。到点响的时候不发请求，
  通知上写的就是你设它时存下的那句话。提醒没有后台轮询或推送。
- 后台朗读仅由前台操作启动，使用媒体通知和系统音频焦点；暂停会释放唤醒锁，闲置五分钟清空队列。
  系统划词和图片选择不需要读取剪贴板、无障碍、悬浮窗、录音或整库相册权限。
- 全程 HTTPS：`usesCleartextTraffic=false`，另有 `res/xml/network_security_config.xml`；
  `res/xml-v37/` 下多一份，只为多写一句 `<domainEncryption mode="enabled"/>`——ECH 要的那个开关，
  targetSdk 低于 37 时它默认是关的。放在 `-v37` 是因为旧解析器不认这个标签，而那个文件里出现
  未知标签是直接解析失败，不是一条警告。
- 会话 cookie 存在系统的 `CookieManager` 里，OkHttp 通过 `WebViewCookieJar` 读写同一份（这样它
  跨进程重启也还在）；App 不存储账号密码，密码只在提交那一刻过一遍内存。
- **本机不存站点内容，只存你自己的动作。** SharedPreferences 里是：外观、检查更新的时机、
  上次查到的 release tag，以及浏览历史、读到哪儿了 / 追帖、钉住的板块和排序、提醒、屏蔽规则、
  域名解析的开关和服务器地址（连同它们各自的开关）。没有帖子正文、没有收藏、没有通知或私信，也没有 HTTP 缓存——每个屏幕上的
  东西都来自它自己打开时发出的那次请求。里面确实存着标题和用户名，但那是「你打开过它 / 你写了这条
  规则」的记录，取回新的一页之后跟着更新。站点图片仅作内存缓存；用户草稿、主动保存的图片和截图编辑副本另行保存。
  草稿按账号保存在本机，只有用户点击上传或发布才会提交到站点。OCR、二维码识别在设备上处理图片，
  后台朗读使用离线声音；站点和媒体请求、更新检查、域名解析仍需要联网。
- 「应用设置 → 本机数据」把上面每一样列出来，每一样都能单独关掉或清空，也能一次全清。
- 域名解析 (DoH) **默认开着**，所以第一次打开 App 就会有第三个出站地址：你选的那台 DoH 服务器
  （出厂是 `dns.telekom.de`）。七个预置的都是公开的第三方 DoH，跟本项目没有关系；它们
  收到的只有「要解析哪个域名」，没有 cookie、没有 `Referer`，也不知道你在站点上做了什么。
  **没自己选过服务器的时候，这个地址会自己变**：出厂那台答不上来时，App 在后台向剩下六台预置各发一次
  查询（都是同一个 `linux.sb` 的 A 记录），然后换到答得最快的那台上去，此后一直用它。也就是说那一刻
  这六个第三方各收到一次「有人在解析 linux.sb」。这件事最多十分钟一次，自己在卡上选过一台就不会发生。
  关掉它，域名就交回系统解析——只剩一处例外，写在这儿而不是藏着：**Android 17 及以上**的设备上，ECH
  取那把公钥仍然会问这台 DoH 服务器（`HTTPS` 记录，每个域名每半小时最多一次，取不到也记着不再问），因为
  一把从明文 DNS 里取来的公钥可以被同一个中间设备换掉，拿它加密等于没加密。它问的还是只有「这个
  域名的 HTTPS 记录是什么」。低于 Android 17 的设备上没有那个接口，也就没有这个请求。
- **App 不再在本机开任何监听口。** 以前有一个：一个只转发 `CONNECT` 的回环口，为了把 DoH 和分片
  送进登录那个 WebView。它没有口令（`ProxyController` 的代理加不了），所以同一台手机上的别的 App
  也能经它出网。现在登录是 App 自己用 OkHttp 发的，那个口连同它的这条代价一起没了。
- **QUIC 回退不是新的出站地址。** 它连的还是 `linux.sb` 自己那两个地址，只是把 TCP/443 换成
  UDP/443；首次由 TCP 失败触发，之后会短期复用已成功的通道。地址是 App 用 DoH 解析出来的那一个，用
  `HostResolverRules` 钉给 Cronet，所以 Chromium 那套自带解析器不会绕过 DoH 去问系统。
- 更新检查连接 `api.github.com` 上本项目自己的 Releases。
  这个请求用独立的 OkHttp 客户端发出，不带站点的 cookie 和 `Referer`；`只手动检查` 档位下一次也不发。
  下载的安装包落在 App 自己的 cache 里。`FileProvider` 配置三个专用目录：`cache/apk/`、
  `cache/share/` 和 `files/vision_drafts/`，没有暴露私有目录根路径。对外分享仅授予对应 URI 的只读权限。
  帖子内的第三方媒体、外部链接和 DoH 会连接相应提供方；网络图片识别仅在用户主动选择时取图。

## 已知限制

- 依赖站点的 HTML 结构。改版会打断解析层，这是这类客户端的固有代价。登录现在也在这条线上：
  站点改一个字段名，`ParseTest` 里那六条会红，但改版当天装在手机上的那一版还是登不上。
- OAuth（GitHub / Google）和忘记密码走浏览器，不在 App 里完成——它们要离开 linux.sb 再回来，
  而这个 App 已经没有为此存在的 WebView 了。
- 域名解析 (DoH) 只管解析这一段。地址本来就是对的、连上去之后才被掐断（按 TLS `server_name` 打的
  那种），换谁解析都一样，那一半要靠分片、ECH 或者 QUIC 回退。DoH 服务器自己不通的时候会先用
  之前的答案顶着，连过期答案都没有才静静退回系统 DNS——那意味着「打开了但没生效」是可能的，所以卡上
  会写出上一次失败的原因，也给了一个「测试」按钮。没自己选过服务器的话它还会自己换一台，但**换过去
  的也可能一样不通**：这七台在你这条线路上能不能用，由你所在的网络决定，不由 App 决定。
- ECH 要 **Android 17（API 37）** 才有的系统接口。低于这个版本的设备上它不存在，名字仍然是明文发出去
  的，能做的只有分片和 QUIC 回退。接口是按反射**按形状**取的（`compileSdk` 是 36），手上没有
  Android 17 的真机，所以它在真机上到底有没有真的装上，只能靠「测试」那一行 ECH 去看，不靠这里的承诺。
- **QUIC 回退是一注赌，不是保证。** 它赌的是这条线路只看 TCP 里的明文 SNI，而把 UDP/443 放过去。
  打这一版的机器上这一注是赢的：同一个 `linux.sb` 走 TCP 在 27 毫秒内被注入 RST（比一个 200 毫秒的
  来回快得多，所以是本机附近的盒子），而手工构造的 QUIC Initial 打过去，Cloudflare 八次全有回应。
  但有能力解 QUIC Initial 读 SNI 的设备是存在的（Initial 只用可推导的密钥保护），也有很多网络直接
  封掉 UDP/443。所以它只是 TCP 失败之后的一次重试，不是一条能指望的通路。
- QUIC 回退**只重试能安全重放的请求**：`https` 才试，一次性或双向的请求体不试，证书校验失败不试
  （那说明地址被换了，换个协议重来只会把凭据递给同一个假服务器），已经进入发送阶段的写操作只有
  `GET`/`HEAD` 才会重发——一个可能已经到了服务器的 `POST` 重发一次就是发两次帖。
- Cronet 和内置 OCR 模型会增加包体积。release 按 ABI 分包，更新检查按设备架构挑选；
  通用包作为兼容兜底。当前大小见 1.4.0 验证记录。
- 发帖只能发普通帖。抽奖帖和发卡帖的表单字段多一大截（奖品清单、开奖时间、卡密、面额），
  没做进去。
- 附件支持多选并串行上传；结果不明确时需先核对，再手动确认重试。
- 搜索必须登录，这是站点的限制。
- 图片识别支持单张不超过 16 MB 的位图，按尺寸采样；小字、复杂排版或模糊截图可能需要裁剪和人工纠正。
- 朗读需要系统离线语音包，只涵盖已加载的回复。厂商省电策略和语音引擎会影响后台体验；从最近任务划掉
  应用会停止朗读，重启后不自动恢复队列。
- 头像上传没有裁剪界面。站点是拖拽缩放的裁剪面板，App 按 EXIF 转正后居中裁最大正方形、缩到
  200×200 存 JPEG。
- 个人设置里的「首页无限滚动」（网页端偏好）和「注销账号」（不可逆）没做进来，走「网页版设置」。
- 没有离线阅读。这是选择而不是欠缺：不存内容就不会拿旧内容当新内容显示，代价是没网的时候
  App 什么都打不开（浏览历史那一页还能看，但点开任何一条都要网络）。
- 收藏要登录。它是站点的收藏，游客的帖子页上没有那个表单，所以帖子页右上角也不会出现这个按钮。
- 第三方登录绑定这一跳走系统浏览器：它要离开站点去 GitHub 或 Google 再回来，App 里没有那个 WebView。
- 更新检查只在打开 App 时按你选的时机跑一次，没有后台任务、没有推送；关着 App 不会有人通知你。
- 追帖看板是打开那一页时一个一个去数楼层的（一次并发 4 个），所以帖子多的时候要等一会儿；关着
  App 它不数，也不会有人通知你某个帖子有了新回复——App 里没有任何后台轮询。最多追 20 个。
- 「读到哪儿了」记的是楼层号。楼被删掉或者站点改了分页，位置就可能偏一点——它是个书签，不是
  锚点。找不到那一楼时那条横条不出现，而不是把你扔到一个错的地方。
- 提醒是本机闹钟，能不能准点响归系统管：通知权限关着收不到（设置页会直接说这件事），部分厂商的
  省电策略也会把它推迟。签到提醒只是到点提醒你去签，**它不会替你签**——签到是站点的动作，
  要你自己点。
- 开奖时间读的是站点抽奖卡上那一行。**按人数开奖的抽奖帖没有开奖时间**（「满 500 人自动开奖」），
  所以它只印条件、不给按钮——宁可没有，也不猜一个时间。自己手打「开奖时间：2026-09-05 20:00」的
  帖子（站点没给它抽奖卡）另有一条从正文里认的兜底，认不出来同样不给按钮。
- 本地屏蔽只管**显示**：它不删任何东西，也不告诉站点，换台手机不跟着走。站点自己那份关键词屏蔽
  （只管首页）是另一回事，两份互不影响，屏蔽规则页上有入口过去改。
- 分享成图一次画一楼，不是整个帖子；正文超过 900 字截断（一张卡是引用，不是全文复刻）。图里
  不写你是谁。
- 更新指向 `net/Release.kt` 里的 `Github.REPO` 一个常量。换仓库改这一行，改错了不会有别的后果——
  GitHub 答 404，App 报「还没有发布过版本」。tag 里数字前面的东西一律当装饰忽略（本项目的 tag 是
  `StarBaseV1.0.2`），所以换个命名风格也能比，但 tag 里**必须有版本号**，否则它会被当成版本 0。
- 没有 Gradle wrapper（见上）。
